# East Java province classification update

This update replaces the public training/test marker map with a pixel-classification overlay on satellite imagery. It uses your own extracted pixels to train a separate, balanced pixel-level k-NN classifier. Your existing polygon model and evaluation files stay in place.

The download contains code only. It does not contain province imagery or real province prediction results. Those must be generated on your computer using your Copernicus account. Completed downloads and classification tiles are cached for resuming interrupted work.

## Install the update

1. Stop Streamlit with Ctrl+C.
2. Extract this ZIP into the main `Joni_PSD_UTS` folder containing `requirements.txt` and `uts`. Allow **only `uts/deploy/app.py`** to be replaced. Two new Python modules and a dependency file are added.
3. Use the actual downloaded files, rather than copying a preview, to preserve complete code and indentation.

The original `pipeline.py`, source polygons, original satellite job folders, training/testing CSVs, and polygon model are not replaced.

## Run in Windows PowerShell

Open the terminal in your main project folder:

```powershell
cd "C:\Users\Usser\Downloads\Joni_PSD_UTS\Joni_PSD_UTS"
```

### 1. Install processing dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -r uts/code/requirements-province.txt
```

### 2. Train the separate pixel model

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py train
```

This requires the existing `uts/data/csv/training/piksel_train.csv` and `uts/data/csv/testing/piksel_test.csv`, generated by your original completed extraction and `pipeline.py train`. The script verifies that polygon IDs are disjoint between training and testing. It uses the same eleven features but trains directly on pixels, with equal class sample counts and k=5. Original polygon-model scores do not become province-map accuracy.

### 3. Inspect the province plan without submitting jobs

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py plan
```

Default settings: September 2026, **100 m classification grid**, **100 km processing tiles**, and **5 km coastal buffer** around East Java. The plan prints the tile count and approximate study area. The study includes the province mainland, Madura, offshore islands, and the stated coastal strip, rather than the whole surrounding ocean rectangle. Check your Copernicus processing credits before the next step. These are NEW province jobs; the original 18 sample-extraction tiles are not repeated.

The coarse grid keeps a province demonstration manageable. It samples aligned Sentinel-2 observations with nearest-neighbor resampling; it is not native 10 m/20 m Sentinel-2 detail and should not be used for fine boundary measurements. Set `--resolution 20` for finer processing if resources allow, using a fresh output folder. The script never silently mixes resolutions or date settings.

### 4. Download province satellite data

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py download
```

Authenticate through the printed device link if requested. A saved refresh token may skip the link. Jobs run sequentially to keep account concurrency conservative. Keep your computer awake and connected. Processing time depends on jobs, backend queues and network speed; it is much larger than sample extraction. If a transient error interrupts a run, repeat the same command. Completed downloads are skipped and active jobs are resumed by their saved IDs.

### 5. Classify and export map layers

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py classify
```

This produces categorical raster tiles locally, georeferenced transparent class PNGs for the map, class counts/percentages/areas, the study boundary and completion metadata. Results are published only after every planned tile has been processed successfully. Cloud/NoData pixels remain transparent and are excluded from class percentages. The dashboard reports valid-data coverage, so completed tile processing is not confused with 100% valid satellite observations.

### 6. Restart the dashboard

```powershell
.\.venv\Scripts\python.exe -m streamlit run uts/deploy/app.py
```

The new raster map appears automatically after step 5. It has five class layers, a legend, opacity control, optional reference polygon boundaries, full-screen view, and statistics from your own predictions. It has no TRAIN/TEST badges. Before province processing finishes, the honest fallback shows only digitized reference polygons, with no training/testing markers.

You can also run all processing in one command after checking the plan:

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py run
```

## Changing processing settings

If you change dates, resolution, tile size or coastal buffer, rename `uts/data/province_processing` before the fresh run. Keep the same parameters on plan, download and classify. Do not delete your original `uts/data/csv/hasil_s2_piksel` folder.

For example, after renaming the province-processing folder:

```powershell
.\.venv\Scripts\python.exe uts/code/province_classification.py plan --resolution 50
.\.venv\Scripts\python.exe uts/code/province_classification.py download --resolution 50
.\.venv\Scripts\python.exe uts/code/province_classification.py classify --resolution 50
```

## Publishing

For Streamlit, push both `uts/deploy/app.py` and `uts/deploy/classified_map.py`, and the entire generated `uts/deploy/province_classification` folder (including every PNG under `layers`). Keep your existing deploy dependencies. Classification runs locally; the deployed dashboard only reads the exported assets, so it does not need Copernicus credentials, scikit-learn or rasterio at runtime.

Do not push `uts/data/province_processing`, downloaded raw GeoTIFFs or credentials. Add `uts/data/province_processing/` to your repository's `.gitignore`. Keep the pixel model/metadata locally as evidence; these can be stored alongside your original model for reproducibility.

## Interpretation

The original polygon metrics still evaluate 75 held-out polygon means. The new pixel model is evaluated using pixels from the held-out polygons, and the app labels its metrics separately. Neither evaluation verifies every unsampled location across East Java. Local training labels, seasonal vegetation, coastal transitions and geographic similarity can affect generalization. There is no “unknown” classifier class: outside cloud/NoData masks, the five-class model assigns one of its known classes.

Class percentages are based on valid 100 m grid cells inside the study boundary plus coastal buffer. They are not copied from the reference screenshot and may differ substantially. Missing observations are not replaced with fabricated classifications.

## Verification

Checked with isolated temporary fixtures: balanced pixel training, disjoint polygon IDs, resume/settings protection, raster inference, georeferencing, transparent NoData, class counts/percentages, coverage, preservation of completed exports after partial failures, five map layers, class toggles, opacity control, and Streamlit pending/complete states. No synthetic results are packaged. Authenticated province satellite jobs and actual province predictions must be run on your machine and have not been executed here.
